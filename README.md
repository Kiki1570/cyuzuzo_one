# Computer Deposit Tracker

Admin-only web application for tracking computer deposits and retrievals. Built with React, Express, Node.js, and MongoDB Atlas-compatible MongoDB.

## Behavior

- The first administrator is created through a one-time setup screen. Once an administrator exists, setup is permanently closed.
- Only an authenticated administrator can add people/computers, view records and history, or change a status.
- New records start as **Not deposited**.
- Admin actions move a record between **Deposited** and **Retrieved / withdrawn**. Each action is timestamped and records the administrator and optional note.
- Search/filter, summary counts, CSV export, and print-friendly reports are included.
- No end-user accounts or public record views exist.

## Deploy to Render with MongoDB Atlas

The repository includes `render.yaml` to create the API and frontend services together. Render hosts the application; MongoDB Atlas stores the persistent records. You need to create the Atlas database and provide its connection string.

### 1. Prepare MongoDB Atlas

1. Create a MongoDB Atlas project and cluster, and create a database user with a strong password.
2. In Atlas **Network Access**, allow connections from Render. For a straightforward initial setup, `0.0.0.0/0` allows network access from any IP, so use a strong database password and least-privilege database user. If your Atlas plan and deployment support fixed outbound IPs, restrict the access list to those instead.
3. Choose **Connect → Drivers**, copy the Node.js connection string, replace the password placeholder, and set the database name to `computer_deposit_tracker`. Keep this URI private.

### 2. Deploy the GitHub repository

1. Sign in to Render and choose **New → Blueprint**.
2. Connect GitHub and select `Kiki1570/cyuzuzo_one`.
3. Render reads `render.yaml`. Enter the Atlas URI when prompted for `MONGO_URI`; Render generates a secure `JWT_SECRET` automatically.
4. Create the Blueprint. It deploys `computer-deposit-api` and `computer-deposit-tracker`; the frontend API URL and backend CORS origin are linked automatically.
5. Wait for both services to finish deploying. Open the frontend service URL and create your first administrator account.

Never commit the Atlas URI or other secrets to GitHub. If you have already exposed a database password, rotate it in Atlas immediately. The first admin setup endpoint is disabled once an admin is created.

### Render service configuration

The Blueprint configures:

- API root: `backend`; build `npm install`; start `npm start`; health check `/api/health`.
- Frontend root: `frontend`; build `npm install && npm run build`; publish `dist`.
- `MONGO_URI`: provided privately in Render with the Atlas URI.
- `JWT_SECRET`: securely generated by Render.
- `VITE_API_URL` and `FRONTEND_ORIGIN`: service URLs linked with Render `fromService` references.

If you use custom domains, update `FRONTEND_ORIGIN` in the API service to the exact frontend origin (scheme and hostname, no trailing slash). The frontend variable is baked into the static build, so redeploy after changing it.

## Run locally

1. Configure the API:

   ```bash
   cd backend
   cp .env.example .env
   # Edit .env and set MONGO_URI and a long random JWT_SECRET
   npm install
   npm run dev
   ```

2. In another terminal, run the web app:

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

3. Open http://localhost:5173 and create the first admin. Local MongoDB or an Atlas URI can be used.

## Requirements

- Node.js 18.18+ (or Node 20+)
- MongoDB local or Atlas connection string
- Render account for hosting

## API overview

- `GET /api/health` — service health
- `GET /api/auth/setup-status` — whether initial setup is available
- `POST /api/auth/setup` — create the first admin only
- `POST /api/auth/login` — admin login
- `GET /api/auth/me` — current admin (auth required)
- `GET /api/admin/records` — list/search/filter records (auth required)
- `POST /api/admin/records` — create a record (auth required)
- `PATCH /api/admin/records/:id/status` — mark deposited/retrieved and append history (auth required)
- `GET /api/admin/summary` — status totals (auth required)

All record and summary endpoints are protected on the server, not merely hidden in the UI. Do not commit `.env` files. Use HTTPS and a strong, unique JWT secret in production.
